# DOCUMENTATION.md — 文档与治理配置规范

> 细则文件。由 `AGENTS.md`（AI 执行规则）路由表加载，适用于纯文档、规则、索引和不影响业务运行的治理配置修改。
> 标记规则：只有【强制】、【应当】、【可选】决定优先级。

## 文档职责

- 【强制】`README.md`（项目说明）负责项目入口、运行方式、目录地图和文档导航。
- 【强制】领域术语文件（如 `CONTEXT.md`）负责领域术语、关键业务边界和事实来源；除非任务明确要求，不把运行手册或历史流水追加进去。
- 【强制】`AGENTS.md`（AI 执行规则）是规则唯一人工维护源，镜像文件（如 `CLAUDE.md`）只做完整镜像。
- 【强制】`VERSION_HISTORY.md`（版本历史）记录版本变更与验证，不承担待办清单职责。

## 设计文档生命周期

- 【强制】ADR（架构决策记录）、设计方案和实施计划必须在正文开头包含"状态"小节，状态只使用：草稿、已接受、已实施、已替代、已归档。
- 【强制】状态为"已实施"时，记录实施提交或可定位的版本历史证据及最后核验日期。
- 【强制】状态为"已替代"时，记录替代文档路径；不得静默覆盖历史决策。
- 【应当】历史正文保持原样，状态更新、实施证据和索引属于允许追加的治理信息。
- 【强制】交接包/索引文件必须覆盖目录内全部对应文件。

## 内容与引用

- 【强制】代码式标识在首次出现和关键位置补充中文含义，连续重复且语义明确时可省略。
- 【强制】仓库内 Markdown 链接使用相对路径，并确保目标存在。
- 【应当】命令示例标明适用 shell；优先沿用仓库既有示例使用的 shell，无既有示例时按团队主流环境给出。
- 【应当】避免写死会随测试增长而过期的数量；确需记录时注明采集日期和生成方式。

## 文档任务完成清单

- [ ] 文档职责与入口描述一致，没有把同一事实维护成相互独立的多份来源。
- [ ] 内部链接、索引覆盖和状态字段通过治理检查。
- [ ] 方案实施任务已核对完成定义、禁用清单和偏离自检。
- [ ] 未改动用户明确要求保持不变的文档或规则语义。
- [ ] 已检查 `git diff`（文件差异），确认只包含本轮文档和治理配置。
- [ ] 已向用户汇报修改、校验、提交和推送状态。

## 工具链配置附录（docs/agents/）

- 【强制】`docs/agents/*.md` 是 engineering skills（to-tickets / to-spec / code-review 等）的工具链配置附录，描述"issues 存哪、domain docs 在哪"——不是行为纪律细则，不与 `.rules/` 重复。
- 【强制】`docs/agents/*.md` 与 AGENTS.md 的 `## Agent skills` section 同属唯一权威源；如存在镜像（如 CLAUDE.md），由镜像脚本同步，不在镜像里单独维护第二份工具链配置。

### 领域文档职责边界（三者不重复维护同一事实）

| 文档 | 回答什么 | 谁来读 | 变化频率 |
|---|---|---|---|
| `CONTEXT.md` | 系统讲什么语言、术语什么意思、关键业务边界 | engineering skills（由 `docs/agents/domain.md` 指示） | 慢 |
| `docs/adr/*.md` | 为什么做这个架构/设计决策 | engineering skills（由 `docs/agents/domain.md` 指示） | 只增不改 |
| `.rules/FEATURE_MAP.md` | 每个模块当前应有什么行为、哪些已知坏了 | AI 改代码前必读（AGENTS.md「二、功能地图维护」节） | 中 |
